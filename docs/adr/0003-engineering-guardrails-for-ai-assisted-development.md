# ADR-0003: Engineering guardrails for AI-assisted development

- **Status:** Proposed
- **Date:** 2026-11-25
- **Deciders:** Project owner
- **Related:** [ADR-0002](0002-baseline-technology-stack.md)

## Context

Most code will be generated by AI assistants, and every line must still be defensible. The faster code is
generated, the more we need fast, automatic feedback that catches wrong or inconsistent code before review.

## Decision

We will set up the following guardrails before any domain code:

| Guardrail | Tooling |
| --- | --- |
| Compiler strictness | `backend/Directory.Build.props`: nullable, latest analyzers, code style enforced in build, **warnings as errors** |
| Real-infrastructure tests | xUnit + `WebApplicationFactory` + **Testcontainers** (PostgreSQL 18, Kafka 4.1), no fakes for infrastructure |
| Single API contract | OpenAPI exported on build to `backend/openapi/claims-api.json` (committed); frontend types generated with `openapi-typescript`. CI fails if either is stale |
| Input validation | FluentValidation validators, auto-registered from the API assembly |
| Repeatable local DB | Migrations and `IDataSeeder`s applied on startup when `Database:MigrateOnStartup` is true (Development/tests) |
| Frontend style | angular-eslint (with template accessibility rules) and Prettier |
| End-to-end | Playwright (API mocked by default, `@stack` specs against Compose) |
| CI | GitHub Actions: backend build and test, contract check, frontend lint, format, test, build and e2e, compose build |
| Consistent context | `AGENTS.md` / `CLAUDE.md`, Angular best-practice files, MCP servers (Angular CLI, Playwright), `/new-rfc`, `/new-adr`, `/journal` |
| Line endings | `.gitattributes` forces LF everywhere |

## Consequences

- Mistakes surface as build, lint or test failures rather than in review.
- Integration tests need Docker. On this Windows machine, Smart App Control blocks locally built test DLLs, so
  `scripts/test-backend-in-docker.sh` runs the suite in the SDK container.
- Warnings as errors slows down quick experiments a little.

## Alternatives considered

- **In-memory EF provider / mocked Kafka in tests**: faster, but hides real behaviour (SQL translation, broker semantics).
- **Hand-written frontend DTOs**: no tooling, but they silently drift from the backend.
- **openapi-fetch client**: bypasses Angular `HttpClient` (interceptors, `HttpTestingController`); types-only generation keeps `HttpClient`.
